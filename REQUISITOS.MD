## 2. Checklist Detalhado dos Requisitos Técnicos Obrigatórios (Oracle PL/SQL)

Todos os scripts devem ser desenvolvidos e homologados para o **Oracle Database (19c / 21c / 23ai)**, garantindo execução idempotente, ausência de erros de compilação e saída formatada no buffer (`SET SERVEROUTPUT ON`).

### 2.1. Modelo Relacional Oracle (DDL & DML)
- [ ] **Modelagem Mínima:** Mínimo de **4 (quatro) tabelas inter-relacionadas**, modeladas na 3ª Forma Normal (3FN) e aderentes ao domínio *CitizenTech*.
- [ ] **Integridade Referencial e Restrições (Constraints):**
  - Definição explícita e padronizada de Chaves Primárias (`PRIMARY KEY` – `PK_...`), Chaves Estrangeiras (`FOREIGN KEY` – `FK_...`), Restrições de Unicidade (`UNIQUE` – `UK_...`), Obrigatoriedade (`NOT NULL` – `NN_...`) e Validação de Domínio (`CHECK` – `CK_...`).
- [ ] **Geração de Identificadores:** Uso de `GENERATED BY DEFAULT AS IDENTITY` ou objetos `SEQUENCE` dedicados para gerenciamento das chaves primárias.
- [ ] **Scripts DDL Limpos:** Inclusão de cláusulas de limpeza prévia (`DROP TABLE ... CASCADE CONSTRAINTS`) no topo do script para permitir reexecução limpa pela banca avaliadora.
- [ ] **Carga Inicial de Dados (DML Seed):**
  - Inserção mínima obrigatória de **10 (dez) registros de teste por tabela** (totalizando no mínimo 40 `INSERTs` válidos para 4 tabelas).
  - Dados consistentes, realistas e coerentes com o cenário *CitizenTech* (proibido o uso de dados genéricos como `"Teste 1"`, `"aaa"`, `"123"`).
  - Finalização explícita da transação com `COMMIT;`.

### 2.2. Bloco Anônimo PL/SQL (`DECLARE ... BEGIN ... EXCEPTION ... END;`)
- [ ] **Declaração e Inicialização de Variáveis:** Uso de variáveis escalares com tipagem forte ou ancorada (`%TYPE` / `%ROWTYPE`) e inicialização adequada na seção `DECLARE`.
- [ ] **Consulta Direta (`SELECT ... INTO`):** Recuperação de dados reais das tabelas do projeto atribuindo os valores diretamente às variáveis locais declaradas.
- [ ] **Saída Formatada Obrigatória:** Impressão clara dos resultados consolidados via `DBMS_OUTPUT.PUT_LINE`.
- [ ] **Tratamento de Exceções Básicas:** Implementação obrigatória do bloco `EXCEPTION` tratando explicitamente:
  - `WHEN NO_DATA_FOUND THEN` (registro inexistente para o filtro informado).
  - `WHEN TOO_MANY_ROWS THEN` (consulta escalar retornou mais de uma linha).
  - `WHEN OTHERS THEN` (captura segura com `SQLCODE` e `SQLERRM`).

### 2.3. Estruturas Condicionais (Tomada de Decisão)
- [ ] **Estrutura `IF / ELSIF / ELSE`:** Implementação de lógica condicional multinível em PL/SQL.
- [ ] **Regra de Negócio Real e Justificada (*CitizenTech*):** A estrutura condicional deve resolver um problema prático do domínio do projeto, tais como:
  - *Cálculo dinâmico de SLA e prioridade de chamados públicos* (ex.: Crítico, Alto, Médio, Baixo).
  - *Classificação de nível de risco ambiental ou desastres urbanos* (ex.: Alerta Vermelho, Laranja, Amarelo, Verde).
  - *Triagem inteligente de atendimentos ao cidadão ou índice de vulnerabilidade comunitária*.
- [ ] **Saída Auditável:** Exibição do estado avaliado e da decisão tomada pela regra via `DBMS_OUTPUT.PUT_LINE`.

### 2.4. Estruturas de Repetição (Looping)
- [ ] **Iteração em Lote:** Implementação funcional de laço de repetição utilizando `FOR ... IN`, `WHILE ... LOOP` ou `LOOP ... EXIT WHEN`.
- [ ] **Processamento Prático:** Percorrer múltiplos registros ou intervalos para realizar totalizações, simulações de indicadores públicos, atualização de status em lote ou geração de relatórios operacionais no console.

### 2.5. Cursor Explícito
- [ ] **Ciclo de Vida Completo do Cursor:**
  1. **Declaração (`CURSOR c_nome IS ...`):** Consulta SQL envolvendo preferencialmente junções (`JOIN`) entre tabelas correlacionadas do projeto.
  2. **Abertura (`OPEN c_nome;`):** Alocação do contexto ativo da consulta em memória.
  3. **Leitura Iterativa (`FETCH c_nome INTO ...`):** Extração linha a linha dentro de um `LOOP` controlada pelo atributo `%NOTFOUND` (`EXIT WHEN c_nome%NOTFOUND;`).
  4. **Fechamento (`CLOSE c_nome;`):** Liberação obrigatória dos recursos de memória ao término do processamento.
- [ ] **Exibição de Dados Correlacionados:** Impressão estruturada de cada linha processada e resumo final (ex.: total de registros lidos via `%ROWCOUNT`) utilizando `DBMS_OUTPUT.PUT_LINE`.

### 2.6. Procedimentos Armazenados (Stored Procedures)
Devem ser criadas e compiladas **2 (duas) Stored Procedures** (`CREATE OR REPLACE PROCEDURE`) acompanhadas de seus respectivos blocos de teste/execução:

- [ ] **Procedimento 1 – Operação Transacional / DML:**
  - **Objetivo:** Inserção, atualização ou mudança de estado transacional em uma ou mais tabelas do sistema (ex.: registrar uma nova ocorrência cidadã, atualizar o despacho de uma equipe de atendimento).
  - **Assinatura:** Uso obrigatório de parâmetros de entrada (`IN`) tipados adequadamente.
  - **Requisitos Internos:** Validação de dados de entrada, controle transacional (`COMMIT` em caso de sucesso, `ROLLBACK` em caso de erro) e bloco `EXCEPTION` com mensagens claras via `DBMS_OUTPUT.PUT_LINE`.
- [ ] **Procedimento 2 – Consulta Analítica / Processamento em Lote:**
  - **Objetivo:** Cálculo de indicadores, classificação em massa, auditoria de SLA ou consolidação analítica de dados do projeto *CitizenTech* (ex.: relatório consolidado de chamados por região/severidade).
  - **Assinatura:** Uso de parâmetros `IN` / `OUT` (ou `IN OUT`) e/ou emissão de relatório formatado detalhado via buffer (`DBMS_OUTPUT.PUT_LINE`).
  - **Requisitos Internos:** Agregações, cursores ou regras de negócio aplicadas sobre a base populada e tratamento de exceções.
